# S5 复杂工作流的开发期改进证据

本文是后续 S6 留出评测和 S7 创作的开发材料，不是运行期自动学习、发布或执行器。

| 可泛化经验 | 本轮证据与已采用处理 | 后续评测重点 |
| --- | --- | --- |
| 参数必须按模型验证 | 匀速窗口与 Kalman 噪声使用独立约束；Kalman 不接受窗口；无效非默认参数拒绝 | 保留互斥参数、边界和重复配置反例 |
| 冻结前先规范化默认值 | 首轮因整数默认值恢复为浮点数导致计划摘要改变；增加默认值校验和往返验证 | 同计划确认/恢复/重复调用摘要恒定 |
| 原数值 API 返回形状也属于契约 | 旧 build_track 返回 track/duplicates 二元组；误用被数值测试拦截 | 旧 M4/M5/M6 oracle 与单位/时域不漂移 |
| 合成源不能代替真实数据适配器测试 | 真机冒烟发现 MaterializationRepository 需显式数据库对象；已加契约用例 | 真实源少量服务器内读取与缺失阶段版本策略 |
| 部分成功与全部失败分开 | keep_partial 保留成功航班；全失败保存失败报告，不能写 partial 掩盖 | 混合失败、全失败、零结果和 stop 分别检查 |
| 兼容性在批准前校验 | 报告复用仅接受当前已验证 S5 工作流结果；旧 H5 多图协议仍由原 HTTP 读取 | H6 再设计跨协议/时间轴转换，不悄悄丢弃图形或换口径 |
| 恢复不能生成新逻辑试验 | SIGKILL worker 后复用独立后端执行号；配置重复则有新的 repeat/trial 身份 | 每个已准入单位调用计数和完整来源链 |
| 固定样本统计须明确范围 | batch_statistics 的范围为 approved_frozen_sample；S5 不覆盖旧全库视图 | 防止报告把局部统计写成全批次结论 |
| 技能仍由文档表达流程 | 新技能正文组织样本、物化、试验、评估与报告，Python 仅执行单元和控制授权/持久回执 | 留出场景比较工具效果与结果，不只检查 skill_view 调用次数 |

固定配置样例在 `config/workflows/`；其参数复用当前可经 API/助手使用，H6 再提供编辑与套用界面。S5 的一次真实合成 Agent 通过不作为 S6 稳定性结论。
