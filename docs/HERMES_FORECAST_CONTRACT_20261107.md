# 精确观测窗口与未来预测契约

2026-11-07开始。开发纪律：服务器优先，Python只用已有Anaconda（scat-agent/scat-hermes），前端只用已有Node24/npm11；不创建环境、不安装依赖、不用venv/uv。临时目录限两端项目`.tmp/forecast-contract`，正式证据`var/validation/20261107-forecast-contract`。现有5175工作台与18152/18153代理保留，服务器18120平台、18121主Agent、18124作者、18126后台Agent及其他既有服务保留。SSH口令仅进程内存；不回传生产数据库或原始轨迹。用户授权补齐契约并沿用必要生产切换授权，服务器不得重启。

目标：精确“最后200点”独立于秒数窗口；从最后观测点向未来预测，与历史截止点回测明确区分。没有可验证真值时保留预测且不生成误差指标。最终修复已上线并完成真实页面确认、CPU计算、制品和刷新回读验收；早期失败与回退记录保留。

## 业务契约

| 场景 | 方案参数 | 观测与真值 |
| --- | --- | --- |
| 末点向未来预测 | `kind=forecast`、`observation_last_n=200`、`forecast_origin=last_observation` | 按时间排序的最后200个观测点；末点为唯一预测起点，不取未来真值、不计算误差 |
| 历史批量回测 | `kind=comparison/experiment`、`forecast_origin=historical_cutoffs` | 保留原M6历史截止点协议；可用`observation_last_n`精确限制每个起点之前最后N点 |
| 指定历史时刻回测 | `forecast_origin=as_of`及带时区的`as_of` | 必须等于真实观测点的时刻，不静默向前移动；仅起点之前的点进入模型，之后数据只用于匹配真值 |

“未来”相对于已冻结的最后观测时刻，不是服务器当前时刻。时域10/30/60秒产生三个相应未来目标点。没有匹配真值的目标时刻仅返回缺失原因，不产生零误差、MAE/RMSE/ADE/FDE或空样本误差表；有效预测不会因没有真值被判失败。历史回测仅对实际配对的时刻聚合，缺口/越界不参与误差分母。后来到达的数据不自动改变已批准预测或补算指标。

点数范围为3..2000，严格整数；不足、重复时间戳、无效坐标或窗口缺口超限均拒绝准备，不补点、不把200当200秒。CPU点数模式使用完整N点输入；匀速模型取该窗口实际时间跨度估计速度，不再隐藏截为默认120秒，也不允许再叠加模型`window_s`。`stride_s/min_observed_s/max_cutoffs_per_flight`是原历史截止点选择参数，不用于把点数窗口换算成秒数；未来预测每架只有一个末点起点。

真库未来输入直接调用有界时间尾部投影，不使用原20,000点前缀查询冒充末尾。确认前冻结观测起止UTC、实际点数/跨度、源序号摘要、目标时刻及内容摘要；`ModelInputReference`同步精确点数和起止时刻。任务、步骤、独立执行和报告沿用归属、摘要、批准清单及幂等执行号校验。确认后数据变化不移动预测起点；刷新读取原制品，不重新预测。

例如：

```json
{
  "kind": "forecast",
  "batch": "scat20161015_20161021",
  "external_ids": ["100002"],
  "models": [{"model": "constant-velocity-heading"}],
  "observation_last_n": 200,
  "forecast_origin": "last_observation",
  "horizons_s": [10, 30, 60],
  "max_flights": 1
}
```

仍需在页面核对后点击确认，聊天文字不替代确认。确认卡区分“从末次观测向未来预测”和“历史回测”，显示实际点数、起点与跨度；结果分别标注预测摘要和预测轨迹，同一预览位置切换。

## GPU边界

生产GPU没有在本轮启用，仍以实际workflow目录登记为准。GBAR精确原始窗口最多500点，同一批准窗口交给固定预处理，重采样为36个10秒输入时刻；实际窗口须满足其350秒等条件，不能偷偷补为500点或读取更早上下文。未来输出使用10秒网格、不超过360秒，并裁为批准时域；缺真值不得调用误差评估。已用既有合成传输后端验证200原始点、36重采样时刻、禁止补读、三个目标输出及重复执行号不重发，不将合成通过说成真实CUDA验收。

- 回读修复后定位到结果集合`analysis_artifacts_hermes_h7b`残留旧`uq_analysis_artifact_run_kind`，阻止同一运行保存摘要和轨迹页。已核对运行代码使用非唯一run/kind索引，确认所有计算均终态且原任务报告可验证，再仅删除这项旧索引；制品ID唯一性、owner/TTL索引、全部既有文档保留。原任务随后发布成功、CPU calls仍为1。以后精确窗口方案在采样和确认前检查多页存储准入，兼容性不满足即拒绝，不等计算后才发现。
