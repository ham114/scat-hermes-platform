## 2. 项目定位与范围

### 2.1 项目目的

建设面向 SCAT/UAV 航空数据分析与轨迹预测验证的智能平台，在复用已有业务能力的基础上，引入 NousResearch Hermes Agent 负责自然语言任务编排，通过 MCP 调用受控业务工具，由 FastAPI 统一提供认证、业务 API、会话入口和结果访问。

工程目标是掌握并实际落地 Hermes 的模型接入、工具注册、MCP、流式对话和服务化集成，形成能演示、能测试、能说明边界的项目。业务目标是让查询、轨迹分析、质量检查、RAG、模型任务和结果可视化继续可用，并具备可追溯的执行记录。

### 2.2 目标用户与主要场景

| 用户 | 主要场景 | 期望产出 |
| --- | --- | --- |
| 航空数据分析人员 | 按批次、呼号等条件检索航班，查看概览、质量和轨迹 | 可复核的统计、表格、轨迹图 |
| 轨迹预测研究人员 | 准备模型任务、确认执行、查看评估和模型对比 | run、指标、版本信息和 artifact |
| 平台开发人员 | 增加业务工具、接入模型、排查调用链 | 清晰的服务边界、契约测试和日志 |

### 2.3 目标业务闭环

```text
用户在门户或对话入口提出问题
  -> FastAPI 验证身份并建立会话、运行映射
  -> Hermes 根据工具说明选择业务工具
  -> MCP 校验参数、调用权限及可信执行上下文
  -> 应用服务访问 MongoDB、RAG 或模型执行后端
  -> 返回结构化结果、run_id / artifact_id 和必要证据
  -> FastAPI 适配事件，前端展示文字、表格、图表和任务状态
```

模型任务采用“准备方案 -> 用户确认 -> 提交任务 -> 查询状态 -> 查看结果”的闭环。统计、预处理、数值计算和模型评估由确定性代码执行。

### 2.4 首阶段范围

优先跑通一个 Hermes 对话入口、一个 MCP Server、一个外部 DeepSeek LLM 接口，以及航班检索、数据概览、轨迹查询、质量检查、RAG 五类代表性只读能力。随后迁入模型任务确认、执行和结果恢复。

暂不进行大模型训练、全库重构、数据库迁移、全部工具的一次性改写，也不把本平台用于实际航空运行指挥。原始航迹不直接当作文本知识库导入；RAG 用于业务文档、术语、指标口径等适合检索的材料。

## 5. 目标架构与复用边界

### 5.1 采用 C 方案

```text
Vue 门户 / 客户端 / 过渡 Streamlit
          |
          v
Nginx：客户端统一入口
          |
          v
平台 FastAPI：认证、业务 API、会话映射、事件与结果适配
          | HTTP + SSE（具体端点以固定 Hermes 版本验证结果为准）
          v
独立 Hermes 服务 ------------> DeepSeek 外部 API（默认）
          |                  -> llama-server（后续可选）
          | MCP
          v
SCAT MCP Server：工具白名单、参数与上下文校验
          |
          v
共享应用服务：查询 / RAG / 任务准备与提交 / 状态 / 结果
          |
          +--> MongoDB / run 与 artifact 存储
          +--> 外部 RAG 服务
          +--> 独立模型执行后端
```

平台的确定性 REST API 继续直接调用应用服务；不要求普通页面查询绕经 Hermes。MCP Server 直接复用业务应用服务，避免复制计算逻辑或无必要的 HTTP 回环。需要跨进程复用 HTTP API 时，仅包装经过授权、稳定且有明确契约的端点。

### 5.2 各层责任

- **FastAPI**：认证与授权、可信用户上下文、平台 thread/run 与 Hermes session/run 的映射、事件适配、恢复和结果访问。
- **Hermes**：对话与工具选择、参数补全、结果解释；业务授权和任务确认仍由业务服务强制校验。
- **MCP**：仅发布批准的业务工具；进行 schema、调用身份和上下文校验，限制输出体积、超时与错误暴露。
- **应用服务**：业务规则、任务确认、执行、幂等、数值计算、持久化与归属校验。旧 Agent Tool 和新 MCP Tool 都是薄适配层。
- **模型与检索服务**：独立运行与依赖环境，记录模型身份、参数和版本；不把整个模型环境安装进 Web API 环境。

### 5.3 工具迁移规则

先选五类只读工具完成一条真实链路，再按业务域迁移。不得将现有全部 REST 接口自动暴露为 MCP 工具。模型任务工具统一采用 prepare / submit / get / list 等稳定边界，不把整个旧主 Agent 作为一个黑盒工具交给 Hermes。

`user_id`、owner、授权范围与可信 `thread_id` 从服务端验证后的上下文取得，不接受模型生成的同名参数作为身份凭证。服务间认证与用户身份传递分开设计，普通工具参数不能赋予越权能力。确认码绑定用户、会话、工具与规范化参数，具有有效期且只能消费一次。

Hermes 原生工具可能带有终端、文件、网络等能力；本业务入口默认只启用必需能力，在固定版本上验证白名单和禁用结果。工具返回文本作为数据处理，不能据此获得新增权限。

以下为目标结构；application、hermes_runtime、scat_mcp、services/hermes、environments 已创建，其余以实际落地为准。

## 6. 开发环境与开发纪律

### 6.1 环境管理硬性要求

1. **本机与远程服务器全部使用 Anaconda 内的 Python 环境；禁止在项目目录创建 `.venv`、`venv` 或其他项目内 Python 环境。** 不执行 `python -m venv`，不使用默认会在项目内建环境的 `uv sync`、`uv run` 工作流。
2. Python、pip、pytest、uvicorn、Streamlit 均通过目标环境的 Python 调用：激活后使用 `python -m ...`，或使用 `conda run -n <环境> python -m ...`，或明确指定 Conda Python 的绝对路径。
3. 不将依赖安装到系统 Python、Anaconda base 或项目内 `.tmp/site-packages`，不通过 PYTHONPATH / PYTHONUSERBASE 注入临时依赖作为正式运行方案。`src` 源码路径配置不属于依赖注入。
4. `scat-agent` 可复用，但环境共用不意味着可以随意升级。安装或升级前记录环境清单、做版本差异与依赖冲突检查；避免影响原平台。Hermes 依赖冲突时新建独立 **Conda** 环境，例如 `scat-hermes`，不得退回 venv。
5. 不直接运行可能自动创建 `.venv` 的 Hermes 默认安装脚本。H1 核查固定版本的安装和启动方式，采用显式 Conda Python 安装，并验证运行及子进程的 `sys.executable`、`sys.prefix`。
6. Conda 管理环境，项目锁文件管理依赖版本。保留 `pyproject.toml` / `uv.lock`，环境导出清单作为实际安装记录；它们职责不同。需要由 uv 导出或安装时，必须显式选择 Conda 解释器并验证目标，不隐式建环境。
7. 正式依赖包含在可审查、可重建的服务级锁定输入中。Hermes 已提供 Conda 定义、安装入口和上游版本/源码记录，传递依赖实装快照按验证记录归档；不得把手工 `pip freeze` 当作唯一的依赖设计。
8. Node.js / npm 按 `package-lock.json` 使用 `npm ci`。`node_modules` 是 Node 依赖目录，不是 Python venv；不提交源码仓库。

### 6.4 路径、配置与服务纪律

- 仅在新项目开发，不回写原项目；同步前比较本机和服务器差异，保护远端未合并改动。
- 不提交真实 `.env`、数据库 URI、令牌、账号、业务数据、模型权重和私有日志。示例配置只列键与无敏感占位值。

- 新服务使用独立状态目录、测试数据标识和未占用端口；不覆盖现有生产 SQLite、会话和 artifact，不在共享 GPU 上无控制并发。

## 10. 当前风险与处理顺序

| 风险 | 已知情况 | 处理方式 |
| --- | --- | --- |
| 共用 Conda 环境 | `scat-agent` 同时服务旧平台 | 先复用现有依赖，不盲目升级；有冲突则另建 Conda 环境 |
| Hermes 协议与依赖 | v0.22.3 已固定，平台 3.12 / Hermes 3.14 隔离 | 实际接口与工具事件按固定版本验证，升级需重新验收 |
| V100 共享显存 | LLM 加载采样差值约 19.34 GiB；未测并发峰值 | 先限制单并发，再做 LLM/RAG/GBAR 共存测量 |
| GPU 容器条件 | NVML 版本不一致；标准 GPU 请求未通过 | 维护窗口处理驱动和 Toolkit/CDI；不将诊断挂载当作部署方案 |
| 原生引擎兼容 | 已测预编译引擎要求高于宿主 glibc | 固定兼容镜像或验证其他构建，不升级宿主 glibc 解决开发问题 |
| 磁盘 | 历史采样系统盘 95%、`/mnt` 96% | 启动下载、构建或部署前重查；镜像与日志也需容量规划 |
| 模型解释质量 | 小样本中文输出有指标口径不严谨问题 | 以业务契约与 RAG 证据约束，保留人工复核题集 |
| 状态重复与迁移 | 新旧编排检查点格式不同 | 显式映射，不直接共用；历史会话迁移不纳入首个 POC |

| D-07 | Compose 分步引入，GPU 条件单独验收 | 当前标准 GPU 容器、磁盘和共享资源仍有前置问题 |
| D-08 | 权重继续放 `/mnt`，源码只存配置与身份记录 | 避免重复下载、仓库膨胀和镜像携带权重 |
| D-09 | 第一阶段默认 DeepSeek 外部 API，本地 LLM 后置 | 遵循用户最新要求，先完成业务集成 |
| D-10 | Nginx 统一接收客户端请求 | 平台 API、对话流和页面共用入口，内部服务不直接对外暴露 |
| D-11 | Vue 门户保留动态结果编排和对话，展示能力不降低 | 复用 AnalysisResult、ECharts/Cesium；七类旧结果与原交互逐项对照，前端仍按 H6 计划推进 |
